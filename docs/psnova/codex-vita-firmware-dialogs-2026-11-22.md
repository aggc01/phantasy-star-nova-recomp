# Nova Vita firmware dialogs

Done by Codex, 22 November 2026.

The original Vita save picker and IME work are paused at the player's request. The ordinary PC launcher continues with the recomp's own dialogs.

The screenshots from the normal launcher show the English PC dialogs. The native firmware work runs under `dump/codex-firmware-dialogs` with independent save directories. The normal launcher remains on the verified PC build while the native paths are tested.

## Save and load

- Added the Vita 3.74 AppMgr slot-file adapter in `runtime/core/apputil.c`. The save plug-in reads slot existence at offset `0x28` in a `0x228`-byte snapshot. It then reads each selected `0x400`-byte parameter record by slot ID. The adapter reads the existing `0x34c`-byte marker metadata and applies the existing English translation to the display copy.
- Added P8 paletted texture support to the GXM descriptor reader and shared decoder. The GPU cache detects palette writes separately from index writes. The capture writer now stores palette addresses. The new replay build produced identical draw output for a 53-line comparison on the existing version 1 Nova capture. A compiled decoder fixture passed linear and Morton addressing, component swizzle, and an in-place palette change. [Vita3K descriptor layout](https://github.com/Vita3K/Vita3K/blob/master/vita3k/gxm/include/gxm/types.h#L1055) · [VitaSDK formats](https://github.com/vitasdk/vita-headers/blob/master/include/psp2/gxm.h)
- The first isolated run after these changes counted one slot-file open, three metadata reads, and one close. Native PAF opened `app0:/saveicon.png` and then dispatched through its PNG transform table to uncompiled ARM code at `0x901b9838`. The caller installs that address explicitly at `0x90175fcc`. Both the copied and live save hashes matched their pre-test values.
- Added seven ARM-mode seeds in `recompiler/seeds/libpaf-3.74.txt`. They come from the firmware's two transform tables and are specific to Vita 3.74. Reanalysis found all seven ARM entries and preserved the original staged memory blocks and variable bindings. Pass `--seeds recompiler/seeds/libpaf-3.74.txt@0x90000000` when analysing the staged PAF at `0x90000000`.
- The seeded run returned success for copied slots 0, 1 and 2. It executed the previous missing function and reached `0x901b9a98` in PAF's PNG filter. The recompiler now handles integer VABDL and VABD. A compiled fixture passed on the exact unsigned opcodes, including large differences and an output register that overlaps an input.
- Bound the firmware dialog's registry language query to Nova's language setting. The common-dialog main module asks for `0x00037502`, the system language, before showing its native text. [VitaSDK registry parameters](https://docs.vitasdk.org/group__SceRegistryMgrUser.html)
- After the PNG filter fix, the original picker drew three rows with Nova's icons. Both `native-vabd-02900.png` and `native-vabd-03300.png` under `dump/codex-firmware-dialogs/runs/save-list` show the firmware layout. The text was blank and the Circle pulse did not select a slot. The log `before-libSceFt2.log` showed that the PVF loader could open the two system fonts but called unresolved SceFt2 exports.
- Staged the original Vita 3.74 `libSceFt2` library, including the two exports PVF needs during initialization. Added its signed high-word multiply instruction to the recompiler. A compiled fixture passed using the exact SMMUL opcode from the font library with positive and negative products at signed limits.
- The first SceFt2 run stopped in a bounded Thumb jump table. Its branch at `0x9501606a` reached `0x95016d86`, which the original function analysis left outside the dispatch. The analyser now bounds and follows this form of register-indexed Thumb switch. The test confirmed that the branch and its target share one owner and that reanalysis preserves the guest memory image.
- The next font-enabled run passed the original font initialization and the copied-slot reads. Cross closed the dialog and the guest received its result. The frame was black and the GPU log showed that PAF's native framebuffer-reading shader at `0x903008c8` could not translate SOP2. Added SOP2 to the GPU translator and corrected the software interpreter to work on packed RGBA words. The exact 13-instruction PAF shader translated to a 6,513-word SPIR-V module with framebuffer fetch. The registry bridge returns the same system button-assignment value as the runtime's AppUtil handler. Nova's actual slot-selection input in this test was Circle.
- The SOP2 run drew all three original rows again. Down highlighted the third row, visible in `native-sop2-03000.png` under `dump/codex-firmware-dialogs/runs/save-list`. No row text appeared. Cross completed the firmware dialog, but no slot payload opened and Nova returned to the title. Both save trees matched their starting hashes.
- Circle selected the highlighted entry and Nova called `sceSaveDataDialogContinue`. The firmware read that slot's second-stage metadata. The confirmation stayed black through frame 3400 and Nova had yet to open the slot payload.
- Capture `nova-native-dialog-f2990.vfc` shows that the SOP2 shader uses a 400×62 P8 texture for the selection effect. The 12 PAF draws in that frame are the close button, row backgrounds, icons, information buttons, selection effect, and a small strip. The capture contains no separate glyph-atlas draw. The missing labels now need investigation on the PAF/PVF side as well as a second-session render check.
- The targeted module trace confirmed that the original Latin and Japanese font faces open and provide metrics. PAF called `scePvfGetCharInfo` 28,898 times for the first letter `L` and never called `scePvfGetCharGlyphImage`. In the confirmation capture `nova-native-dialog-f3180.vfc`, PAF began a scene and submitted zero draws. The captured stack places the repeating metrics call in PAF's text layout route through `0x900964e4`, `0x90095e1a` and `0x9019bd62`. The text cursor remains at index zero. The same run selected slot 2 and reached the confirmation, and its delayed Circle pulse did not open `savedata2.bin`.
- The VFC captures are in the Codex workspace output directory on C. The staged run logs are retained on F. Use the probe's `--capture-frame` and `--capture-output` for a new single-frame capture, and `--trace-module scePvf,SceFt2` to trace the original font calls. The font trace is large when the layout loop persists.

## Controller keyboard

- The retail shell's IME initialization entry is at `0x8113e642` in the local 3.74 shell image. It creates auxiliary state at `0x81140562`, constructs the `0xa0`-byte service at `0x8113e4d8` and starts it at `0x8113e2e4`. The constructor sets up `SceImeServerDispatch`, `SceImeClientList`, and `SceImeEventQueue`. Startup passes `SceImeService` to the original IPMI exports `391B02AA` and `2B646CEA`, which the staged `libshellsvc` already provides. Nearby handlers call the original PAF plug-in lookup exports, both present in the staged `libpaf`, to resolve `ime_plugin`.
- The original client wrapper at `0x9300b2fe` passes the pipe name to `sceKernelOpenMsgPipe` and stores a successful handle. The previous probe reached the wrapper, then failed to connect. The IPMI module also imports named event flags and vectored pipe sends that the current kernel shim lacks. A probe still needs to start the original service with its required PAF and kernel state, verify its request dispatch, and composite the plug-in into Nova. The PC keyboard path remains available from the normal launcher.
