# Maintainer notes: Phantasy Star Nova Recomp, Windows release 0.1.0 Beta 1

These notes are for whoever builds and shares the release. They are not for players. The player-facing instructions are in [README.md](README.md). Delete this file from the download if you do not want to share it.

## Before you share this folder

1. **Remove the font.** Delete exactly one file: `localization\fonts\glenthregular.ttf`. Keep `localization\fonts\ATTRIBUTION.md`. It is the only copy of Glenth Regular in the release. Setup then asks players for their own copy (README step 1, the **Get Glenth font** button, and the message in the setup log). Nothing else needs to change, and setup still passes with a font the player chooses. The font's embedded notice reads `OWPIctures - All rights reserved`. No separate license came with it, so check your own license before you decide to keep it in a download.
2. Make sure there is **no `NovaData` folder** next to `setup.py`. It holds the builder's own game data, saves and settings. A clean release has none.
3. Zip the folder so it extracts to a single folder. `engine\release\ffmpeg-6.1.1.tar.xz` and the other FFmpeg notices must stay in the download: the bundled FFmpeg executable is GPLv3.

### Changes made to the engine for this release

The release engine matches the development tree for the UI, input, graphics, overlay and audio code. These files differ on purpose:

- `runtime\core\player_paths.h` (new), `io.c`, `fios.c`, `apputil.c`, `ui\save_backups.c`: guest saves, save backups and deleted saves are kept under `RECOMP_SAVE_ROOT`, so they sit outside the replaceable build. `fios.c` now uses the same path resolution as `io.c`.
- `packs\PCSG00351\hooks.c` and `pack.toml`: the Arabic right-alignment hooks are removed. The two extra function seeds are added.
- `pipeline\vitarecomp.py`: a plain (unencrypted) update with its own ELF no longer needs the base game's license, and a native ELF dump that kept the `eboot.bin` name is accepted.
- `decrypt\vitadecrypt\pkg.py` (PKG import, 25 November 2026): `extract_pkg` used to read the whole PKG into memory (about 3.3 GB for Nova) and then hold a decrypted copy of each file. It now checks the file table first and streams each file in 8 MiB chunks. `inspect_pkg` reads a PKG's identity and file table from a forward-only stream, which is how setup looks inside a ZIP. Before anything is written, every entry must lie inside the file, every name must be safe on Windows (no `..`, absolute or drive paths, `:` or other forbidden characters, reserved device names such as `CON`, trailing dots or spaces), no two names may differ only by case, and no file may sit inside a name that is also a file. Self-test: `python -B -m vitadecrypt.pkg --selftest` from `engine\decrypt`.
- `decrypt\vitadecrypt\game.py`: the PKG's outer layer is extracted to a `.add-pkg-*` folder beside the output folder instead of the system temp folder, so gigabytes of scratch stay on the release drive and one pattern (`.add*`) names everything an interrupted import can leave.
- A dev-checkout patch for the two files above is `Nova PKG QA\evidence\engine-decrypt-changes.patch`. The development checkout was not changed.
- The `Play Nova.exe` launcher (`engine\release\play_nova.c`) sets `RECOMP_SETTINGS`, so the game reads and writes only `NovaData\Player\settings.ini` and never touches `%APPDATA%\ProjectNativ`.

### Default settings

On first setup, `NovaData\Player\settings.ini` is created once with: `input_mode = auto`, `render_scale = 4`, `frame_rate = 60`, `sharpen = 0.507067`, `fullscreen = 0`. Setup never overwrites an existing file. The 4× scale and the 60 FPS target are what the 22 November 60 FPS investigation ran with on an RTX 5060 Ti (`docs/psnova/codex-fps-investigation-2026-11-22.md`). I could not trace where the sharpen value 0.507067 (51%) came from. The code default is 0.35 and the development library's own settings files do not set it, so decide whether to keep it. **4× is heavy for weaker GPUs.** To ship a gentler default, change `render_scale` in `setup.py` (search for `render_scale = 4`) to 2. The pack's rendering fixes (sRGB, deferred draws, depth clip) are compiled in through `RUN_ENV` in `pack.toml`.

## How setup works

1. **It reads the inputs** (`setup_sources.py`), and nothing is written except `NovaData\setup-inputs.json`, which remembers the selected paths so the window can reopen them. The player gives a base PKG and an update PKG, or one ZIP with both (CLI: `--game`, `--update`, and `--license` for the game's `work.bin` or `.rif`); extracted folders, and a PKG mixed with a folder, still work from the CLI.
   - A **PKG** is identified from its header, its embedded `param.sfo` and its (unencrypted-key) file table, with no license. The file table is checked as well: offsets, Windows-safe names. A **ZIP** member is recognized by the `\x7fPKG` magic, not its name, and read forward-only for the same header. Directories, other files, add-on (DLC) PKGs and other titles' PKGs inside a ZIP are skipped, with a note.
   - The roles come from the headers, not the field or the file name: `PCSG00351`, content ID `JP0177-PCSG00351_00-NOVAAPPLICATION0`, **one app package with category `gd` and version `1.00`** and **one patch package with category `gp` and version `1.05`**. A file the player chose directly must be a usable package, or setup stops and names it. A problem with something found *inside a ZIP* matters only if it leaves a role empty: a ZIP with update 1.04 and 1.05 uses the 1.05 and notes the 1.04; a damaged DLC PKG in the ZIP is noted and skipped. A role matched twice (two base PKGs, or the ZIP and the Update field both holding a 1.05) is an error that names every file and ZIP member.
   - A base PKG without a license inside needs `--license`. The license must be 512 bytes (or NoNpDrm's 1024) and carry Nova's content ID. A PSN-account license is accepted with a warning (the pipeline only keeps NoNpDrm-kind licenses, and a real wrong key stops the import with a clear message). The embedded work.bin of a PKG is detected in its file table.
   - Folders keep the checks they always had: `param.sfo` identity, the archives, `eboot.bin`, the `sce_pfs` files, the license size, the `disc1` and `sce_module` files.
   - Then it checks the SHA-256 of `PSVUPDAT.PUP` (3.74) and the font. Each failure names the file or version it expected.
2. It computes a build ID from the release version, the firmware, the font, every localization file except the font, **every file under `engine\decrypt`, `dev`, `packs`, `pipeline`, `recompiler`, `runtime` and `third_party`**, the SHA-256 of every file in an extracted folder input, **the SHA-256 of each package's own bytes (a PKG, or a PKG inside a ZIP after unzipping, so the same PKG gives the same build ID loose or zipped)**, and the license's 512 bytes. A changed input produces a new build under `NovaData\installs\<build-id>`. Reading a ZIP member to hash it also finds a damaged ZIP (bad CRC) before anything is built. The toolchain and Python are pinned by `version.txt`: bump it when you change them.
3. It runs the stages: firmware, base, update, import, analyze, recompile, build, English text, English movies. After each stage it checks the outputs and records it in `progress.json`. The recompile stage also verifies the generated labels, and the import stage verifies the layered `libc` and `disc1` files by hash. A rerun skips finished stages and redoes a stage whose output is missing.
   - **Base and update stages with packages.** Each starts by deleting the scratch an earlier, interrupted import can leave (`NovaData\scratch` and every `.add*` folder in the build's library). A ZIP member is then streamed to `NovaData\scratch\imports\base.pkg` (or `update.pkg`), hashed while it is written and compared with the hash taken for the build ID (a ZIP that changed in between is refused), imported with `vitarecomp add <file> --license <license> --no-build`, and deleted. A PKG chosen directly is read where it is. The same SHA-256 checks as for folders (`BASE_FILES`, `PATCH_FILES`) run on the result before the next stage, with wording that blames the package. A failed import shows its last log line first and says when the license did not decrypt the package.
4. It writes `language.txt` and `default.txt`, creates `NovaData\Player` once, copies `Play Nova.exe` to `Phantasy Star Nova.exe`, points `NovaData\current.txt` at the new build, and then deletes older builds under `NovaData\installs`. Locked files are retried at the next run.
5. The original game files, firmware and font are only read. Saves, backups, screenshots, logs and settings live in `NovaData\Player` and are never touched by setup.

The setup process holds `NovaData\setup.lock`, so two copies cannot run at once. The install needs about 14 GB free and takes a while: the recompile and Windows build use every core.

## How the release folder was built

1. Copy the engine from the development checkout at commit `5d30e61` plus its working-tree edits into `engine\`. Apply the changes listed above. Add `localization\`: the English recipes exported from `dev\psnova` and `dump\psnova-l10n` (English only, no Arabic) by `export_text.py`, which lives in `.nova-text-verification` beside the development checkout and is not part of the release, plus the build scripts `build_text.py` and `build_movies.py`.
2. Compile the two launchers from `engine\` with the bundled Clang:

   ```powershell
   & toolchain/llvm-mingw/bin/x86_64-w64-mingw32-clang.exe -O2 -Wall -Wextra -Werror -mwindows -municode -static release/play_nova.c -o "release/Play Nova.exe"
   & toolchain/llvm-mingw/bin/x86_64-w64-mingw32-clang.exe -O2 -Wall -Wextra -Werror -mwindows -municode -static release/setup_launcher.c -o "../Setup Phantasy Star Nova.exe"
   ```

   Both commands compile without warnings, and the output is the same size as the shipped files. The bytes differ because the PE header carries a build timestamp, so the shipped binaries are the ones that were tested.
3. Run `powershell -ExecutionPolicy Bypass -File engine\release\prune_release.ps1`. It removes Python's docs, test suite, pip and build files, the Arm and i686 compiler targets, and the compiler's debugger and linter. This takes the folder from about 1.2 GB to about 760 MB. Run the clean-folder test **after** pruning.
4. Never run `engine\python\python.exe` in the release folder without `-B`: it writes `.pyc` files. The prune script removes them.
5. Remove the font (see above), then zip.

To update the release: copy the new engine files over, rebuild the launchers if their sources changed, prune, and test again from a fresh folder. Players extract over the old folder and run setup. Changed engine or localization files rebuild automatically.

**Input, through `Phantasy Star Nova.exe`**
- **Keyboard and mouse**, with real Windows events: the game's own input record shows Return as Start (`0x8`), W driving the left stick to its forward limit, and mouse movement driving the right stick. The log reports `input: keyboard and mouse`.
- **Controller**, with SDL virtual gamepads in a test-only variant of the release runtime (`window.c` plus a relay, linked with the same generated code): hot-plugging a pad, canceling the load picker with B, failing over to a second pad when the first is removed, choosing a save row with the stick and D-pad and confirming with A, then both sticks, D-pad, face buttons and L reaching the game after the load. The copied saves were the only ones touched. The development saves were read-only and unchanged by SHA-256. The first run of this scenario failed while 16 compiler processes were saturating the CPU, and it passed on both installs once the machine was idle. It needs an idle machine.
- **Quit.** A first close request opens the quit card and a second one quits. Both runs end with no process left behind.

**Setup window**: it opens from the executable with no arguments and creates nothing on disk. Once you start a setup it remembers the game (PKG, ZIP or folder), update, license and firmware paths, even if the setup then fails. It leaves the font field empty when the bundled font is in use, and the Play button is enabled. A saved path that no longer exists is not prefilled.

**Not verified**: Windows 10 (the tests ran on Windows 11); a PC or VM that has never had development tools installed (the setup environment is cleaned and the bundled Python is started with `-E -s -B`, but the test PC does have them); a physical gamepad; a full campaign playthrough; weaker GPUs at 4×.

## Known limits

- **Font license.** See the first section.
- **Text source.** The English message text began as the fan rePatch wording and was revised afterwards (`localization\text\messages.json`). Check its redistribution status before you share it widely.
- **Coverage.** Some menus, lines and screens still use the original Japanese. This is the state of the localization, not a defect of the installer.
- **Seven story movies differ from the dev library's installed archive** in the position of the subtitle backing bar only. See "What was verified". The bar's size and position come from the renderer in `localization\movies\subtitles.py`.
- **Two entries differ from the 21 November English archive in the dev library.** `msg_10323.rmd` (the "Lv." label, which the dev archive re-draws in Glenth) and `msg_100010050005000.rmd` (an unused developer placeholder) are in that archive but not in the build. The current builder rule skips rows whose English equals the Japanese apart from spacing, and both rows are of that kind. Every other entry is identical.
- **New text not yet seen in the game.** The 40 messages added on 24 November are verified in the archive only. See "Localization pass" above for what remains to check.
- **Controllers.** The controller path was exercised with SDL virtual gamepads built into a test-only runtime variant, not with physical hardware.
- **Defender and SmartScreen.** The built `game_host.exe` is compiled on the player's PC and unsigned.
- **Update PKGs.** No genuine 1.05 update PKG has been through setup. The update-PKG and ZIP paths ran on a PKG repackaged from the extracted 1.05 files and on fixtures. If a real update PKG fails on a field the repackaged one does not exercise (a different `info` table, a name the Windows checks reject, a license inside it), the message names the package and the first thing to look at is `vitadecrypt.pkg.inspect_pkg_file` on it.
- **Failed attempts leave their build folder.** A setup that stops with inputs that name a different build (another license, another package) leaves `NovaData\installs\<id>`, with its firmware and, after a stop in a later stage, its imported game (up to about 6 GB). Only a *finished* setup deletes superseded builds. This was already so for folder inputs.
- **Free space.** The 14 GB check runs before the first stage of a build and stops setup at 13 GB free. Setup with a ZIP also holds the unpacked base PKG (3.3 GB) while it is imported. The check does not count that separately: the 14 GB figure covers it with about 4 GB to spare for the real game.
